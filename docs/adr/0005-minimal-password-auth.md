# Single-password cookie auth instead of Supabase Auth or NextAuth

Deploying the app to Vercel gives it a public URL, so it needs *some* access control even though it will only ever have one user. Supabase Auth (already available since Supabase is in the stack) and NextAuth were the obvious alternatives, but both are built around multi-user concerns — sign-up flows, password resets, session/user tables — that this app will never need. We chose a single password stored in a Vercel env var (`APP_PASSWORD`): a `/login` route checks it and sets a signed, `httpOnly`, secure cookie (signed with `jose`, a lightweight signing library, not a full auth framework), valid for 30 days. `proxy.ts` (Next.js 16's name for `middleware.ts`) enforces the cookie on every route except `/login` and the cron Route Handler, which is protected separately by `CRON_SECRET`. This is a deliberate deviation from the obvious "just use the auth provider you already have" path — worth recording so a future reader doesn't "fix" it by wiring up Supabase Auth for a user base that will never exist.
