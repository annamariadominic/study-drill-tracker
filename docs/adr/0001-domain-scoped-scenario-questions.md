# Scenario questions cross Subjects but never cross Domains

Scenario questions need to combine multiple Concepts to feel like realistic applied problems (e.g. an ML-powered API needs rate limiting, caching, and model latency reasoning all at once), but combining Concepts from unrelated areas (e.g. System Design and Spanish vocabulary) produces nonsense. We introduced a Domain layer above Subject specifically to draw this boundary: Concepts from different Subjects may combine in a Scenario question only if those Subjects share a Domain. Drills as a whole are similarly scoped to one Domain. This is hard to reverse because question generation and drill composition both depend on the boundary; it's the kind of scoping rule a future reader would otherwise have to reverse-engineer from generated output.
