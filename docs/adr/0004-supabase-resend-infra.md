# Supabase + Resend for the daily due-reminder infrastructure

The daily email reminder must run even when the local web app and the user's laptop are both closed, which rules out an in-app-only scheduler. We chose Supabase (hosted Postgres) for the database, and Resend for sending the email, over self-hosting a cron server or using a heavier platform. This carries real lock-in: swapping either provider later means rewriting the scheduled job and the email integration, and free-tier limits on both could force a migration as usage grows. We accepted this because it's the lowest-ops path to "runs once a day, unattended" for a single-user hobby project.

**Amendment**: the scheduled job itself is a Vercel Cron Job (daily interval, Hobby-tier compatible) calling a protected Next.js Route Handler, not a Supabase Edge Function as originally written here. This decision came after we'd also decided (see project setup) that the Next.js app itself would be deployed to Vercel — once that was true, keeping the scheduling logic in the same TypeScript codebase as the rest of the app was simpler than splitting it into a separate Deno/SQL Edge Function. The Route Handler is protected by a `CRON_SECRET` bearer token check, unrelated to the app's user-facing auth.
